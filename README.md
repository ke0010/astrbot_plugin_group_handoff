# 群聊轮流说话（握手）· astrbot_plugin_group_handoff

一个 AstrBot 插件，解决「同一个群里有两个（或更多）机器人时抢话」的问题，顺带管另外三件小事。

v0.2.0

## 它能做什么

1. **接力**：同一句触发话让几个机器人几乎同时开口时，后开口的先等对方说完，再组装上下文——这样它接话时，对方刚说的那句已经在历史里了。
2. **离场静默**：群里说一句「小红离场」，这个机器人就彻底闭嘴，直到你说「小红回来」。离场期间连被点名也不出声。
3. **点名接话**：点名谁，谁接话；没被点到的闭嘴；都没点名就由最近说过话的那个接；说「你们俩」时两个都接。
4. **用词表注入**：判定进入某种场景后，把**这个机器人自己的**一份词表文件里的小节追加进本轮 system prompt。词表由你自己准备，插件不附带任何文本。

## 怎么做到的

- 挂在 `OnWaitingLLMRequestEvent`（`@filter.on_waiting_llm_request()`）：这个时机在获取会话锁、组装 prompt **之前**，在这里等待不影响别的事情，睡醒后才拼上下文。
- 「发言权」和「状态」都写在一个共享目录里的 JSON 文件：
  - `floor_<群号>.json`：谁正在说
  - `state_<群号>.json`：谁离场、最后说话的是谁、场景状态
- 状态文件只按**群号**命名（不是「平台:群号」），所以同一个群里两个机器人看到的是同一份状态，接力才真的成立。
- 说不出来/崩溃时会靠 TTL 自愈，不会互相等死。
- 用词表注入走 `OnLLMRequestEvent`（`@filter.on_llm_request()`），只改 `req.system_prompt`，不碰别的。

## 安装

1. 把整个 `astrbot_plugin_group_handoff` 目录放进 `<AstrBot>/data/plugins/`。
   **同一个 AstrBot 进程里跑多个平台时，装一份就够**——插件按 `self_id` 区分不同账号。
2. 重启 AstrBot（插件只在启动时加载）。
3. 打开 WebUI → 插件 → 本插件，按需改配置（至少把 `master_ids` 和 `group_whitelist` 填上）。

## 配置

### 通用

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关，关掉完全回到 AstrBot 原生行为 |
| `group_whitelist` | [] | 生效群号，空 = 所有群；私聊永远不生效 |
| `master_ids` | [] | 主人 QQ 号。只有这些人的消息参与离场/点名/场景判定，空 = 任何非机器人消息都算 |
| `shared_dir` | "" | 状态目录，空 = `%TEMP%\astrbot_group_handoff`；拆成多实例时必须指向同一个目录 |

### 接力

| 键 | 默认 | 说明 |
|---|---|---|
| `max_wait_seconds` | 20 | 最多等别人说完多久，超时自己开口 |
| `floor_ttl_seconds` | 120 | 发言权标记有效期，防异常卡死 |
| `poll_interval_seconds` | 0.3 | 轮询间隔 |
| `gap_min_seconds` / `gap_max_seconds` | 1.0 / 2.5 | 对方说完后自己再随机停一会儿，避免贴脸 |

### 离场静默

| 键 | 默认 | 说明 |
|---|---|---|
| `presence_enable` | true | 开关 |
| `presence_enter_words` | 离场、离开 | 离场口令词（消息里「称呼 + 这些词之一」即离场） |
| `presence_exit_words` | 回来、回来了、回归 | 回来口令词 |

### 点名接话

| 键 | 默认 | 说明 |
|---|---|---|
| `mention_enable` | true | 开关 |
| `bot_names` | 平台ID=名字 | 每个机器人叫什么，如 `default=小红;furina=小蓝` |
| `bot_aliases` | 平台ID=称呼列表 | 认名字的别名表，如 `default=小红,红红;furina=小蓝` |
| `mention_group_words` | 你们、你们俩、你们两个、你俩 | 出现这些词时两个机器人都可以接 |

名字只认三种位置：句首、「，/@」后面、或后面紧跟呼语（「小红啊」）。普通句子中间出现的名字不算点名。

### 用词表注入

| 键 | 默认 | 说明 |
|---|---|---|
| `scene_enable` | true | 开关 |
| `scene_strong_words` | 见 schema | 强触发词，出现 1 个就进入（部分词自带例外规则） |
| `scene_weak_words` | 见 schema | 弱触发词，要凑够阈值且至少两种不同 |
| `scene_weak_threshold` | 3 | 同一条消息里弱词要出现几个 |
| `scene_weak_streak` | 3 | 连续几条消息各至少一个弱词也算进入 |
| `scene_end_words` | 见 schema | 收尾词 |
| `scene_end_grace_rounds` | 3 | 收尾词出现后再延续几轮才退出；这几轮里出现强词会重新计时 |
| `scene_vocab_files` | "" | `平台ID=文件绝对路径`，多个用 `;` 分隔；空 = 不注入 |
| `scene_vocab_heading` | 词表 | 取文件里标题含这个词的一整节（从该 `##` 到下一个 `##`） |
| `scene_inject_prefix` | 见 schema | 注入时加在词表前面的说明句 |

**词表文件怎么准备**：自己写一个 Markdown，里面有一个标题含「词表」的二级标题小节，把词写在那一节里就行。例如：

```markdown
## 一、别的什么

...

## 二、词表

- 身体：……
- 动作：……
```

插件在运行时读取文件，只取「词表」这一节，并会在下一轮重新读——改文件不用重启插件。

## 已知边界

- 说话顺序不固定：谁先抢到发言权谁先说。
- 多实例共享状态依赖同一个本地目录；跨机器不通用。
- 场景判定只看主人的消息，按群号分开记状态；私聊不生效。
- 插件内部异常全部吞掉并降级为原生行为，不会卡住回复。
